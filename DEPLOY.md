# Deployment

Two supported topologies. **Option A is recommended** — it is simpler, avoids
CORS entirely, and keeps the SSE kline stream on a direct browser↔API
connection with no third-party edge in the middle.

---

## Option A — Single service on Render (recommended)

One Node process serves both `/api` and the built SPA. `render.yaml` in the repo
root is a Render Blueprint that encodes everything below.

### 1. Database (Neon, free)

1. Create a project at [neon.tech](https://neon.tech) — pick an **EU region**.
2. Copy the pooled connection string. It must end with `?sslmode=require`.

Supabase works identically; use its connection string instead.

### 2. Service (Render, free)

1. Push this repo to GitHub.
2. Render → **New → Blueprint** → select the repo. It reads `render.yaml`.
3. Set the one secret it cannot generate: `DATABASE_URL` (from step 1).
4. Deploy. The build runs `pnpm run build:deploy`, which builds the API, builds
   the SPA, and applies Prisma migrations.

`JWT_SECRET` is generated by Render automatically. Migrations run on every
deploy and are idempotent.

### 3. Verify

```
https://<your-service>.onrender.com/api/healthz   → {"status":"ok"}
https://<your-service>.onrender.com/              → the app
```

## Option B — Vercel (frontend) + Render (API)

Use this if you want the static frontend on Vercel's CDN. The browser then
talks to the API host directly, so CORS must be configured.

### Vercel

`vercel.json` already pins the build to the frontend only — the API server is
never typechecked or built there.

| Setting | Value |
|---|---|
| Framework preset | Other |
| Build command | `pnpm run build:web` (from `vercel.json`) |
| Output directory | `artifacts/crypto-heatmap/dist/public` |

Add one **build-time** environment variable:

```
VITE_API_URL = https://<your-api>.onrender.com
```

This is baked into the bundle at build time, so changing it requires a redeploy.

### Render (API only)

Same as Option A, plus:

```
CORS_ORIGIN = https://<your-app>.vercel.app
```

Without it the API refuses to boot in production when it is not serving the
frontend itself — that guard is intentional.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | **yes** | Postgres. Server exits at boot without it. |
| `JWT_SECRET` | **yes** | ≥32 chars. Server exits at boot if shorter/missing. |
| `NODE_ENV` | production | Enables the production guards. |
| `PORT` | auto | Injected by the platform; honored only in production. |
| `API_PORT` | no | Overrides `PORT`. Used locally. |
| `JWT_EXPIRES_IN` | no | Defaults to `7d`. |
| `CORS_ORIGIN` | Option B only | Comma-separated origins. |
| `BINANCE_API_BASE` | recommended | See the Binance note below. |
| `REDIS_URL` | no | Falls back to an in-process memory cache. |
| `VITE_API_URL` | Option B only | Frontend build-time only. |
| `STATIC_DIR` | no | Override the SPA path; defaults to the build output. |

## Things that will bite you

**Binance blocks US IPs with HTTP 451.** Any US-region host breaks the whole
market pipeline, because in production all Binance REST traffic is proxied
through our API (`/api/binance`). Deploy in Europe and keep
`BINANCE_API_BASE=https://data-api.binance.vision/api/v3` — the official public
market-data host, which tolerates datacenter IPs far better than
`api.binance.com`. This app only calls public endpoints, so nothing is lost.

**Render's free tier sleeps** after 15 minutes of inactivity; the next request
pays a 30–60 s cold start. The first load after a cold start also refetches all
klines because the cache is in-process. Acceptable for a private tool, not for
public traffic.

**Do not run this API on serverless** (Vercel Functions, Lambda). The kline
cache, the Binance proxy cache and the rate-limit buckets are all in-process,
and the SSE stream runs for 30–40 s on a cold cache. Serverless would refetch
from Binance on every cold start and get the IP banned (HTTP 418).

**Neon free autosuspends.** The first auth request after idle takes a few extra
seconds. `/api/healthz` deliberately does not check the database, so an idle DB
never causes a restart loop.

**Secrets.** `lib/prisma/.env` holds real local credentials and is gitignored —
confirm with `git ls-files | grep .env` (only `.env.example` files should
appear). Never set production secrets in a file; use the platform dashboard.

**Access gate.** The app is still behind the private access-code screen
(`src/components/auth/AccessGate.tsx`) before login. It is client-side only, so
treat it as a privacy curtain, not a security control.

## Testing the production build locally

```bash
pnpm run build:api
pnpm run build:web
NODE_ENV=production API_PORT=8090 node artifacts/api-server/dist/index.mjs
```

Then open `http://localhost:8090` — this is byte-for-byte what Option A serves.
